# 🌿 Учебный план (Telegram Mini App)

Веб-планер + дашборд прогресса для quiz_bot_new. Открывается кнопкой в боте
(меню-кнопка «📊 Планер» или команда `/planner`).

## Что делает
- **План:** пользователь выбирает **период** на календаре (с даты по дату),
  добавляет **задания** (квиз или колода) и для каждого указывает **«интервал»** —
  сколько раз пройти за весь период. Активен ровно один план (новый заменяет старый).
  В карточке «Текущий план» можно **дозаписать задание** в активный план кнопкой
  «➕ Добавить задание» — прогресс при этом не сбрасывается (дубликаты игнорируются).
- **Регистрация прохождений — только из интерфейса и до конца.** Задание запускается
  кнопкой ▶ в планере (deep link `?start=pi_<item_id>`), бот показывает условия, и
  прохождение засчитывается **только если довести до конца**. Обычный запуск квиза/колоды
  из бота и остановка на середине (`/stop`, «Стоп») **не** регистрируются.
  Колода засчитывается только через тест «Верно/Неверно».
- **Дашборд:** общий прогресс `пройдено / цель` в % (линия-путь), суммарно правильно/
  неправильно за период, и то же по каждому заданию (заполняющая линия + точность).

## Архитектура
- `webapp/server.py` — aiohttp-сервер в том же процессе, что и бот (запускается из `bot.py`).
  API: `GET /api/dashboard`, `GET /api/plan`, `GET /api/materials`, `POST /api/plan` (создать/заменить),
  `POST /api/plan/items` (дозаписать задания в активный план), `POST /api/plan/delete`.
- `webapp/auth.py` — проверка Telegram `initData` по HMAC-SHA256 (BOT_TOKEN). Без логина.
- `webapp/static/index.html` — весь фронт (один файл, ваниль): календарь периода,
  конструктор плана, дашборд прогресса. Зелёная тема, light/dark.
- `services/planner_service.py` — создание плана, регистрация прохождений, агрегация прогресса.
- Регистрируемый запуск: `routers/planner.py` (условия + колбэки `plreg:*`) →
  `launch_registered_quiz` (`routers/start.py`) / `launch_registered_tf` (`routers/deck.py`).
- Таблицы: `plans`, `plan_items`, `study_events.plan_item_id`, `sessions.plan_item_id`
  (создаются/мигрируются автоматически в `create_all_tables`).

## Запуск (HTTPS обязателен для Mini App)
Telegram грузит Mini App только по HTTPS. Сервер слушает localhost, наружу — через SSH-туннель.

> ⚠️ **cloudflared на этой сети НЕ работает.** DPI оператора рвёт постоянные соединения
> к туннельной инфраструктуре Cloudflare (`unexpected EOF`) — и quick, и named tunnel.
> Поэтому используется **serveo** (SSH, порт 22/443 — проходит сквозь DPI).

### Как это работает (автоматически)
Бот сам поднимает туннель — отдельно ничего запускать не надо:
- при старте бот запускает `ssh -R 80:localhost:8080 serveo.net` (`webapp/tunnel.py`),
- вычитывает публичный URL, добавляет `?serveo-skip-browser-warning=true` (обход заглушки serveo),
- ставит кнопку меню Telegram «📊 Планер» и обновляет её при каждом переподключении,
- всё живёт в процессе бота → поднимается автоматически при перезагрузке (boot-скрипт править не надо).

Включается флагом в `.env`: `TUNNEL_ENABLED=true`. Открывай планер **кнопкой меню в боте**
или командой `/planner` — там всегда актуальный URL.

### Постоянный URL (по желанию)
Случайный `*.serveousercontent.com` меняется при реконнекте (кнопка меню авто-обновляется, но
сохранённые ссылки протухают). Чтобы получить постоянный `https://ИМЯ.serveo.net`:
1. Зарегистрируй ключ (бесплатно, вход Google/GitHub):
   открой `https://console.serveo.net/ssh/keys` и добавь содержимое `/root/.ssh/serveo_ed25519.pub`.
2. В `.env` задай `TUNNEL_SUBDOMAIN=ИМЯ` (напр. `umarquiz`) и перезапусти бота.

### Ручной туннель (альтернатива, если не хочешь встроенный)
Отключи `TUNNEL_ENABLED`, подними туннель сам и впиши статический адрес в `WEBAPP_URL`:
```bash
ssh -R 80:localhost:8080 serveo.net    # выдаст https://xxxx.serveousercontent.com
# WEBAPP_URL=https://xxxx.serveousercontent.com/?serveo-skip-browser-warning=true
```

## Настройки (.env)
| Ключ | Назначение |
|------|-----------|
| `WEBAPP_ENABLED` | поднимать ли сервер (по умолч. true) |
| `WEBAPP_HOST` / `WEBAPP_PORT` | адрес localhost-сервера (127.0.0.1:8080) |
| `WEBAPP_URL` | публичный HTTPS-URL туннеля (пусто → кнопка не показывается) |
| `TZ_OFFSET_HOURS` | часовой пояс для группировки по дням (UTC+5) |
| `WEBAPP_DEV_USER_ID` | user_id для теста в обычном браузере (иначе 0) |

## Локальный тест без Telegram
Поставь `WEBAPP_DEV_USER_ID=<свой_id>` и открой `http://127.0.0.1:8080/` в браузере —
`initData` не проверяется, данные берутся для этого user_id.
